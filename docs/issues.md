# Runtime issue tracker

Investigation started 2026-10-19. Every observed issue is recorded here, including limitations that remain open. Generated reports and captures are under `out/reports`; game assets and saves remain excluded from Git.

| ID | Status | Issue | Evidence / next action |
| --- | --- | --- | --- |
| WIN-001 | Fixed with startup resolution policy | Resizing changes the window but breaks the game's viewport / input alignment. | Render resolution is now selectable instead of hardcoded to 1280 x 720. Native mode uses actual client pixels after applying Windowed/Maximized/Fullscreen, before game initialization. Custom mode uses the selected resolution. That Android surface remains stable for the session; presentation and touch share an aspect-fit viewport. See WIN-007 for the live reconfiguration limit. |
| WIN-002 | Fixed | Windows ghosting is enabled during long guest calls. | `DisableProcessWindowsGhosting` runs before SDL creates a window. New long-loading sessions retained their normal window instead of the DWM ghost encountered in the baseline. This does not remove synchronous loading stalls. |
| BILL-001 | Partially diagnosed / bypass not implemented | `auto_complete` still shows the game's internet error. | INI selects the local provider correctly and fixture callbacks pass. Native HTTP and Nimble network status remain offline, consistent with the reported internet error. The UI test opened the shop and queried catalog metadata; no checkout was submitted, so in-game purchase completion is not validated. Added logs distinguishing empty catalog queries and entry into `purchaseItem`. Granting paid items after a failed real purchase or impersonating a store is outside this fix. |
| BUILD-001 | Fixed | Source directory had no Git history. | Initial source-only baseline commit `055471c`; game content, generated builds and saves are ignored. |
| FILE-001 | Fixed | Duplicate supplied APKs, OBB and extracted APK occupy the project root. | Removed two loose APKs and the source OBB after SHA-256 comparison with the imported installation. Compared all 1,357 extracted files (168,811,772 bytes) with APK entries: zero mismatches. Removed that extraction, the empty Android directory, and unused matching XAPK wrapper metadata. Retained `.runtime` installation and saves. Evidence: `out/reports/source-cleanup.json`. |
| COMPAT-001 | Open | Native imports are still incomplete. | Baseline startup reports 27 unresolved imports. An unresolved import is only an executed failure when the guest calls it. |
| SAVE-001 | Hardened / original cause unconfirmed | One sandboxed restart failed to replace a Nimble JSON file. | `out/reports/resize-before.json` reports `Cannot publish JSON`. Added unique per-writer temporary files, bounded retries for Windows sharing failures, and error codes. Concurrent-write and held-reader tests pass. The same QA save relaunched successfully outside the sandbox. The original failure did not report a Windows code, so its exact cause is not established. |
| WIN-003 | Open | Long synchronous guest loading blocks window input. | Startup/resource decoding produced multi-second frames and Windows ghosting in the baseline. Ghosting is disabled, but moving loading off the window thread is a separate change. |
| WIN-004 | Menu fixed / gameplay HUD recheck pending | Native UI appears cropped at screen edges. | Traced the original DEX: `Graphics_CanSetGLViewScaleFactor` returns true, the initial factor is 0.5, and its setter stores the renderer's selected float. The bridge instead returned false/constant 1 and ignored the setter. Restored the contract with a JNI float regression test. The full menu and bottom controls now fit a 960 x 600 client. The previously cropped game-mode HUD still needs an interactive recheck with the final binary. |
| BILL-002 | Open | Shop shows BUY buttons without prices. | Bundled gem offers render, but configured local platform catalog has zero entries. No real store connection exists; no paid purchase is submitted during testing. |
| BUILD-002 | Environment | Sandboxed MSVC CMake checks fail with C1902 (PDB manager mismatch). | The same pinned toolchain configures/builds and all five tests pass outside the sandbox. This is not an ARM architecture failure despite Dynarmic's final error message. |
| COMPAT-002 | Open | Nimble analytics SQLite database reports disk I/O error. | Portrait restart log reports `TrackerPinDb`, code 10 during `sqlite3_prepare_v2` for `INSERT INTO session`. Added diagnostics show unsupported `fcntl` command 6 (`F_SETLK`) immediately before this error in `out/reports/final-diagnostics.log`. Implement and test POSIX-compatible byte-range locking rather than reporting success without acquiring locks. Gameplay continues; this is separate from the JSON save replacement problem. |
| WIN-005 | Fixed | ANGLE can paint at the outer window origin, overlapping the caption. | Added a dedicated client child HWND and per-monitor DPI awareness. ANGLE uses the child; SDL retains the parent for events and ownership. Geometry smoke checks confirm a positive caption offset, render origin (0,0) within the client, and matching client/render sizes. A real 960 x 600 window visibly starts below its title bar. |
| WIN-006 | Fixed | Render resolution is fixed at 1280 x 720 regardless of the requested startup mode. | Apply window mode before graphics/native initialization. Choose actual startup client pixels or custom dimensions, initialize the Android framebuffer and size hooks first, and preserve the selected native view scale. Fullscreen startup diagnostics confirm a 1920 x 1080 Android target; the game independently selected a 2730 x 1536 intermediate target. |
| WIN-007 | Runtime limitation / stable fallback implemented | Live Android surface changes retain cached intermediate targets and aspect ratio. | Experimental native resize accepted 960 x 600 -> 1920 x 991 -> 1920 x 1080, but retained its original 1228 x 768 intermediate target. Menu visibility and Play input were unreliable after transitions; the final experimental capture was black. Reverted live native reinitialization. The final launcher prepares resolution before initialization, and window resizing only changes presentation. Save and relaunch to change render quality. |
| LAUNCH-001 | Fixed | No native launcher or persisted settings shared with standalone game startup. | Added executable/root/profile/version selection, window and render modes, dimensions, vsync/FPS, volume/mute and optional library/INI paths. All launcher choices use one validated `launcher.json`. Save & Play was exercised through the GUI. Both entry points share startup code and load the same default configuration without needing a running launcher. Configuration roundtrip, relative paths, validation and command quoting have automated coverage. |
| BUILD-003 | Fixed | Only a console game build exists; Release optimization is incomplete. | Added Windows-subsystem `pvz2pc-game.exe` and `pvz2pc-launcher.exe`, retaining the console tool. Release uses `/O2 /Ob3 /Oi /Ot`, first-party `/GL /LTCG`, `/OPT:REF /OPT:ICF` and no incremental linking. Both GUI processes disable Windows ghosting. |

## Validation sessions

- Baseline: copied the existing `validation-google-free-20261019` files/preferences/external data to the separate `qa-resize-20261019` profile. The default profile is not used for testing. Session report: `out/reports/resize-baseline.json`.
- First fixed run: `out/reports/resize-fixed.json`, 7,994 frames, orderly window close, no CPU fault or worker error. Main menu, F11 fullscreen/return, maximize/restore, Play input and gem-offer shop were inspected. The normal menu and shop rendered; prices remained unavailable.
- Portrait restart: same `qa-fixed-20261019` save, `--width 720 --height 960`, report/captures `out/reports/portrait-restart*`. Completed 12,000 frames without CPU faults or worker errors. Main menu rendered with correct letterboxing; a lower-bar click was ignored and the displayed Play button entered mode selection. Entered Adventure, restored the unlocked world nodes, advanced dialogue, toggled to fullscreen, selected Day 3 and reached its in-level tutorial. This is not proof of completing that level or broader worlds.
- Build/test: `out/build-final.log`, all five CTest suites passed, including the independent ARM64 fixture, billing fixtures, concurrent JSON writes and resized native touch serialization. ANGLE smoke: `out/graphics-resize.log`, pixel-verified letterboxing and guest GL state preservation, PNG `out/graphics-smoke/letterbox.png`.
- Final diagnostic binary: `out/reports/final-diagnostics.json`, 1,200 frames at a 960 x 600 starting window, no CPU fault or worker error. Logs identify framebuffer targets and the unsupported `F_SETLK` request. Final ANGLE smoke also checks that an active guest offscreen framebuffer survives presentation/readback and is not mistakenly shown as the Android surface.
- Launcher follow-up: native GUI visually inspected at 125% Windows scaling; changed client size to 960 x 600, saved JSON, and launched `pvz2pc-game.exe` without a console. Log: `.runtime/reports/game-20261019T070228Z-17160.log`. The initial session ended cleanly after 4,105 frames, with client and render origins recorded in the session report.
- Fullscreen preparation experiment: `out/reports/native-fullscreen.json`, 2,400 frames, 1920 x 1080 client and Android target, no CPU fault or worker error. This run preceded the mutable-view-scale repair; it is evidence of startup geometry, not final visual quality.
- View-scale/live-resize experiment: `out/reports/native-verified.json`, 6,000 frames, no CPU fault or worker error. The repaired scale showed the complete windowed menu; maximize and F11 changed the Android framebuffer, but cached targets persisted. This experiment motivated WIN-007's startup-only policy and does not validate live native resolution changes in the final implementation.
- Desktop interaction was stopped by the user with physical Escape. No further Computer Use actions were taken. Final custom-resolution gameplay, standalone double-click, and the repaired gameplay HUD remain interactive validation gaps. The final build/checks are recorded in `out/build-launcher-final.log`; ANGLE geometry/buffer/state checks passed in `out/graphics-launcher.log` before the final startup-only policy adjustment.
