# Android PC Runtime / PVZ2 v0.1.0-alpha.2

Experimental Windows x64 prerelease, 20 October 2026. This update improves the original ARM64 game's compatibility runtime with lower bridge/libc overhead, audio fixes and corrected execution limits. Full gameplay qualification remains incomplete.

## Downloads

- `pvz2pc-v0.1.0-alpha.2-windows-x64.zip`: portable optimized Windows build with the launcher, game, console tools, ANGLE, app-local MSVC DLLs, documentation, performance records and dependency licenses.
- `pvz2pc-v0.1.0-alpha.2-source.zip`: complete tracked source at the release tag, including the new profiling header, graphics entry-point table, benchmark and measurement scripts. Building downloads the pinned dependencies in `cmake/Dependencies.cmake`.
- `SHA256SUMS.txt`: SHA-256 hashes for the two named ZIP files. Compare with `Get-FileHash -Algorithm SHA256` in PowerShell.

Game APKs, OBBs, native game libraries, saves, personal profiles and launcher settings are excluded. The source ZIP is the complete source needed to build the runtime; GitHub also supplies its standard source archives.

## Changes since alpha.1

- Resolve typed ANGLE entry points once per graphics instance, index ELF symbols, and cache frame/native targets with registration/load invalidation. Construct hot-path diagnostics only when a check fails.
- Avoid redundant clearing in malloc-style allocations while preserving calloc/internal zeroing; retain shrinking realloc blocks; scan bounded strings in validated page chunks; marshal the existing guest jump-buffer layout in bulk.
- Add repeatable ARM64 import/host microbenchmarks, comparison tools, optional `--performance-profile` stage/JIT/import diagnostics, and `-ProfileSymbols` builds. Frame quantiles now use bounded storage and report their histogram method and maximum 3.125% bucket width.
- Fix Windows text-mode corruption of Android media/file streams, improve OpenSL ES engine handling, and separate instruction quotas from deadlines. Native drawing retains a 60-second deadline without the former arbitrary instruction quota; cancellation and worker-failure checks remain active.
- Include all optimization support files and the performance JSON evidence in the distribution. Track twelve optimization items, including newly identified trap-page density and JNI cleanup opportunities.

Recorded on 19 October using three warmed runs and 27 samples per case, the combined optimization pass reduced synthetic dispatch time by **40.2%**, GL parameter forwarding by **59.7%**, and a 4 KiB string scan by **97.0%**. These are focused path measurements, not an overall game speedup, a GPU benchmark, or an emulator comparison. See the [performance tracker](../performance-review.md) for raw data, conditions and remaining work.

## Windows setup and update

1. Extract the entire Windows ZIP into a new writable folder on a Windows x64 PC. Keep `angle`, `docs` and `licenses` beside the executables.
2. Install Microsoft Edge WebView2 Evergreen Runtime if needed; HTML consent dialogs require it.
3. Import your own matching content, or select your existing runtime root in the launcher. The tested PVZ2 package is 13.5.1 / versionCode 1063:

   ```powershell
   .\pvz2pc.exe import --root '.\runtime' --apk 'C:\Games\com.ea.game.pvz2_row.apk' --obb 'C:\Games\main.1063.com.ea.game.pvz2_row.obb'
   ```

4. Open `pvz2pc-launcher.exe`, choose the runtime folder and display/audio settings, then **Save & Play**. To retain settings when extracting into a new folder, copy your existing `launcher.json` there or configure the new launcher to use the existing runtime root. Keep a backup of your saves when testing prereleases.

No game content is needed to inspect launcher settings with `pvz2pc.exe settings`. Source builds require the pinned MSVC compiler, CMake and Git; see the [README](../../README.md).

## Validation and limitations

Release preparation checks the pinned MSVC Windows x64 Release build, all seven CTest suites including the independent ARM64 Android fixture, and graphics smoke validation. Packaging checks verify the installed executables, dependency DLLs, documentation/evidence and archive contents, then run the extracted console executable's settings command.

The optimization pass also completed isolated 360-frame profiled and 1,200-frame unprofiled startup/loading sessions without CPU faults or worker errors. Final captures still show loading artwork; these runs do not establish combat performance or full visual/audio equivalence. A pre-existing intermittent Windows staging-directory rename failure in the fixture installer required a retry during optimization validation; it is recorded in the performance evidence.

- The former instruction-quota failure path has been changed, but this release does not claim complete sustained-gameplay qualification across all worlds and APIs.
- Long synchronous guest loading can delay window input. Choose render resolution before launch and relaunch to change it; live window resizing preserves the guest surface and changes presentation/input mapping.
- Online transport, Google Play Games, purchases, advertising and analytics delivery remain disabled; purchases report unavailable.
- Profiling adds clock-read overhead. Its main-CPU wall-time/callback statistics exclude active worker CPUs and are not GPU duration or OS CPU-time measurements. Gameplay FPS improvements and emulator comparisons remain unmeasured.
