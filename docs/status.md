# Implementation and validation status

The implementation is in active development. **Interactive PVZ2 gameplay has reached Ancient Egypt Day 2, and a later launch restored the saved world state. Full release qualification is still incomplete.**

The source includes package inspection/import, an ARM64 ELF loader and Dynarmic backend, guest-call/import marshalling, JNI services, Android storage mapping, an initial Bionic compatibility library, ANGLE graphics marshalling, OpenSL ES audio bridging, and a separate PopCap adapter.

The Windows x64 C++23 release build and all five CTest tests have passed. The independent sample is a real NDK r29 ARM64 NativeActivity APK, executed through Dynarmic with its guest libc++ runtime and no dependency on `pvz2_adapter`. Its checks include exception unwinding, constructors, JNI strings/arrays/references, nested guest callbacks, emulated TLS, pthread synchronization, per-thread Java exceptions and VM attachment, managed callback execution, actual NDK OpenSL ES interface layouts, ARM64 wide variadic formatting with 32-bit wchar_t and Unicode, and persistent file round trips. Dedicated local billing tests cover INI settings, disabled purchases, native purchase callbacks, grant acknowledgement, finalization, restart recovery and duplicate-consumable prevention. Separate audio tests cover queue completion, independent players, pause/resume, gain/mute, and music activity. Package tests cover re-importing downloaded data without replacing conflicting files. Worker-failure tests verify that blocked guest semaphore, mutex, and condition waits produce diagnostics promptly. These results establish a tested subset of the reusable runtime, not full Android support.

The real PVZ2 13.5.1 package has been imported with its matching OBB. Its ELF constructors and JNI initialization complete. The game initializes its native application and resource manager, reads the RSB index from the OBB, and completes setup and restoration for the registered Nimble C++ components. Glu SDK initialization, offline HTTP error completion, profile loading, initial Wwise resources, and bundled configuration loading execute. A **15,191-frame session ended cleanly without CPU faults or worker errors**, rendering the main menu through the original ARM64 game. An intermediate framebuffer was inspected: `out/reports/pvz2-session-015000.png`. A later interactive session reached **Ancient Egypt Day 2** (`out/reports/pvz2-google-free-015000.png`), with native saves advancing from tutorial state to `egypt2`. It exercised the formerly missing Google Play achievement method ten times without failure, then stopped on a missing `vswprintf` while constructing the world screen. That import is now implemented and tested using the real NDK fixture. A **3,600-frame restart completed without CPU faults or worker errors**, restored the world state and exercised `vswprintf` twice (`out/reports/pvz2-progress-restart.json`). Runtime reports enumerate remaining unimplemented imports and identify executed failures.

The separate graphics smoke test has rendered and checked shader output and sampled ETC1 texture data through ANGLE's D3D11 backend. Its PNG is generated under `out/graphics-smoke`. A later **900-frame session completed without worker errors**, loading the title flow and rendering the menu background (`out/reports/pvz2-900-frames.png`). Its audio report records one output stream, 2,401,536 submitted PCM bytes and 3,110 completed buffer callbacks. Audio callbacks now run on a managed guest worker independently of the render loop, including during long loading frames. Physical audibility and sustained gameplay performance remain unqualified. Frame-time distributions include substantial synchronous startup work and are not gameplay benchmarks.

The generic Windows WebView2 smoke test has passed HTML rendering, JavaScript, JSON messages, custom-scheme callbacks and PNG preview capture; its preview was inspected. The PVZ2 adapter displays the original APK consent HTML without entering age or agreement choices automatically. A submitted form reached the original native completion callback, and later launches restored its saved state. Google Play Games is disabled, including its sign-in, achievement and leaderboard paths. Billing defaults to disabled in `ROOT/game.ini`; explicitly choosing `auto_complete` enables an isolated local transaction simulation with native callbacks and a persistent local-test ledger. It neither charges money nor creates Google or EA transactions. Product metadata can come from an optional offline catalog, and the in-game shop flow still needs qualification with matching offer content. Advertising, CMP network requests and HTTP requests remain unavailable and do not fabricate delivered requests, ad rewards or consent. The Glu analytics adapter preserves the SDK's local privacy properties and documented-in-DEX defaults while leaving network event delivery unavailable.

The adapter now reproduces the Java renderer's pre-frame clear and requested frame-rate limit. Input tests caught and corrected the first-touch identifier, monotonic timestamp units and native-owned input header handling. Static and live replay modes support regression investigation through the same host event interface as mouse input. Separate named profiles keep test saves apart from the default profile.

Remaining release gates include broader Java/native coverage across worlds, in-game purchase simulation with matching offer data, audio quality assessment, and a sustained gameplay session that ends without a new missing API. Threaded shutdown, additional guest exception paths, graphics capabilities, additional package versions, and unsupported API paths also require broader validation.

Generated evidence is stored under `out/reports`, with build/test output in `out/build-release.log`. Game installations, saves, backups, and session reports stay in the selected runtime root. Game content is excluded by `.gitignore`.
